# MAUI Step Guide Author (Leomaris Reyes "Block Strategy" Pedagogy)

## Mission

Generate rich, highly engaging, step-by-step .NET MAUI learning guides and UI replications inspired by the world-class teaching style of **Leomaris Reyes** (Microsoft MVP, creator of AskXammy.com and Telerik .NET MAUI UI articles).

The goal is to demystify complex mobile user interfaces for high-school / K-12 students. Instead of overwhelming learners with 300 lines of completed XAML and ViewModel boilerplate, every screen is deconstructed into bite-sized visual and functional **blocks**, built progressively with placeholder anchors, paired with visual mockups, and accompanied by didactic concept explanations.

All guides for this student project are authored in **Hebrew** with English identifiers, following the K-12 student capability rules.

---

## When to Use This Skill

Trigger this skill whenever:
1. The user asks to **create a guide** for a screen, feature, or UI pattern (e.g. *"create a guide for our playlist screen"*, *"how do I replicate this design step-by-step?"*).
2. The `maui-k12-baton-workflow` reaches **Stage 6 (`CODE_LEARNING_REVIEWER`)** and generates documentation for `Learning/MAUI-Learning-Book.md` or a dedicated screen guide.
3. A student needs an accessible, visual, block-by-block breakdown of a design or XAML architecture.

## The 6-Part Pedagogical Architecture

Every guide generated by this skill MUST strictly adhere to the Leomaris Reyes 6-part structure:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. מבוא והשראה עיצובית (The Hook & Visual Target)           │
├─────────────────────────────────────────────────────────────┤
│ 2. איך המדריך בנוי? (The Meta-Frame: 3 Core Principles)     │
├─────────────────────────────────────────────────────────────┤
│ 3. 🔧 הכנת סביבת העבודה ומרחבי שמות (Environment & Namespaces)│
├─────────────────────────────────────────────────────────────┤
│ 4. אסטרטגיית הבלוקים (The Block Strategy - Progressive XAML)│
│    - Canvas / Background (Gradients / Shapes)               │
│    - Main Layout Grid (RowDefinitions & ColumnDefinitions)  │
│    - Block 1: Hero / Media Header                           │
│    - Block 2: Floating Card (Negative Margins / Shadows)    │
│    - Block 3: Dynamic Data / Badges / Chips                 │
│    - Block 4: Actions & Interactive Controls                │
├─────────────────────────────────────────────────────────────┤
│ 5. ✍️ פינת העמקה והבנה מושגית (Checkpoints & Official Docs)  │
├─────────────────────────────────────────────────────────────┤
│ 6. ארכיטקטורת MVVM וחיבור נתונים (State & Commands)         │
└─────────────────────────────────────────────────────────────┘
```

### Part 1: המטרה וההשראה העיצובית (The Hook & Target)

* **Conversational, enthusiastic opening**: Speak directly to the student with warmth and encouragement (*"שמתם לב פעם באפליקציות המובילות למסכים עם גרדיאנטים רכים וכרטיסים צפים שגורמים לכם לחשוב: 'איך מייצרים ממשק כזה מרשים בלי לקרוס תחת הקוד?' היום נלמד לבנות את זה בדיוק — מאפס ועד רמת גימור מקצועית!"*).
* **The Design Challenge**: Clearly state what design challenge is being solved (e.g. Overlapping cards, ambient gradients, dynamic badge tags, responsive grid).
* **Target Preview**: Reference the target mockup screenshot generated in `Learning/Images/<ScreenName>-overview.png`.

---

### Part 2: איך המדריך הזה בנוי? (The Meta-Frame)

Before showing any code, state the 3 pillars of the learning process:

```markdown
### 🧭 איך נלמד לבנות את המסך?
כדי שתוכלו להבין כל שורה ולשלוט בממשק ב-100%, נפעל לפי שלושה עקרונות:
- ➖ **דיאגרמה חזותית מפורקת (The Block Strategy):** נחלק את כל המסך לבלוקים פונקציונליים בצבעים ובשמות ברורים.
- ➖ **קוד מודולרי לפי בלוקים (עם נקודות עוגן):** לא זורקים 300 שורות קוד בבת אחת! נבנה את השלד עם הערות מקום (`<!-- כאן יבוא הבלוק הבא -->`), ונמלא בלוק אחר בלוק.
- ➖ **התקדמות חזותית צעד-אחר-צעד:** לכל בלוק יצורף צילום מסך או הדמיה כדי שתוכלו לראות את המסך מתעורר לחיים שלב אחרי שלב.
```

### Part 3: 🔧 הכנת סביבת העבודה ומרחבי שמות (Prerequisites)

* List required NuGet packages (e.g., `CommunityToolkit.Maui`, `SkiaSharp.Extended.UI`, vector fonts).
* Present exact XAML namespace declarations (`xmlns:`):
  ```xml
  xmlns:toolkit="http://schemas.microsoft.com/dotnet/2022/maui/toolkit"
  xmlns:viewmodels="clr-namespace:MyApp.ViewModels"
  ```
* Register services/handlers in `MauiProgram.cs` if needed.

---

### Part 4: אסטרטגיית הבלוקים (The Block Strategy)

Build the XAML progressively from the outside in:

#### Step 4.0: הגדרת רקע הדף (Canvas & Gradients)
- Teach native brushes instead of static image backgrounds:
  ```xml
  <ContentPage.Background>
      <LinearGradientBrush StartPoint="0,0" EndPoint="1,1">
          <GradientStop Color="#6A11CB" Offset="0.0" />
          <GradientStop Color="#2575FC" Offset="1.0" />
      </LinearGradientBrush>
  </ContentPage.Background>
  <!-- כאן יבוא הגריד הראשי -->
  ```

#### Step 4.1: שלד הגריד הראשי (Main Layout Backbone)
- Explicitly define `RowDefinitions` and `ColumnDefinitions`.
- **Explain the rationale for every row/column**:
  - `Auto`: מתאים את הגובה לתוכן (טקסטים, כפתורים).
  - Fixed (e.g. `240`): תמונות או באנרים שדורשים גובה מוגדר ויציב.
  - `*`: צורך את יתרת שטח המסך (רשימות `CollectionView`, גלילה).
- Always include placeholder comments for remaining blocks:
  ```xml
  <Grid RowDefinitions="240,Auto,*,Auto" ColumnDefinitions="*">
      <!-- בלוק 1: תמונת רקע עליונה (Hero) -->
      <!-- בלוק 2: כרטיס ראשי צף (Floating Card) -->
      <!-- בלוק 3: רשימת פריטים (Items Collection) -->
      <!-- בלוק 4: כפתור פעולה תחתון (Bottom Action) -->
  </Grid>
  ```

#### Steps 4.2 to 4.N: בניית הבלוקים הפנימיים ושילוב תמונות ממוקדות
- Implement one block at a time.
- **Mandatory Visual Snapshot**: Each block MUST include an image of the actual rendered block (`![תוצאת בלוק N](../Images/<ScreenName>-block<N>.png)`) alongside the XAML code. A guide with only a single overview image at the top is NON-COMPLIANT.
- **XAML Line-Breaking Standard (מניעת גלישת שורות קוד בהדפסה וב-PDF)**:
  - אסור לכתוב תגיות XAML ארוכות העולות על 65-70 תווים בשורה בודדת.
  - בכל תגית המכילה 2 תכונות ומעלה, או ביטוי Binding מורכב (כגון `RelativeSource`, `StringFormat`, `Triggers`) — חובה להוריד שורה עבור כל תכונה (Attribute-per-line indent).
  - שבירת שורות תקנית זו מבטיחה תצוגה נקייה בספר הלימוד וב-PDF ללא גלישה אופקית או חיתוך טקסט, ומקנה לתלמיד הרגלי קידוד מקצועיים.
- Highlight specific UI engineering techniques:
  - **Floating Cards**: Use negative top margins (e.g. `Margin="20,-60,20,0"`) over the hero row to create floating overlays.
  - **Modern Rounded Borders**: Use `<Border StrokeShape="RoundRectangle 24" StrokeThickness="0">` with soft `<Shadow>`.
  - **Pill Badges**: Use small Borders for tags with horizontal stack layouts.
  - **Text Styling**: Use `Label.FormattedText` and `<Span>` for rich typography.
  - **Adaptive Themes**: Use `AppThemeBinding` for seamless Light/Dark mode transitions.

### Part 5: ✍️ פינת העמקה והבנה מושגית (Didactic Callouts)

Whenever an essential or tricky concept is introduced, insert a dedicated pedagogical callout:

```markdown
> [!TIP]
> ### ✍️ פינת העמקה: למה בחרנו בשוליים שליליים (Negative Margin)?
> שימו לב לערך `Margin="20,-60,20,0"` שנתנו לכרטיס הראשי!
> הערך השני (`-60`) מושך את הכרטיס למעלה אל תוך השורה הקודמת, ויוצר אפקט של כרטיס "צף" מעל תמונת הרקע. זו הדרך המקצועית לבנות ממשקי מובייל מודרניים בלי להסתבך עם שכבות מיקום מוחלטות (`AbsoluteLayout`).
> 
> 🔗 להרחבה על מיקום ורווחים: [Microsoft Learn - MAUI Margin and Padding](https://learn.microsoft.com/dotnet/maui/user-interface/layouts/margin-and-padding)
```

---

### Part 6: ארכיטקטורת MVVM, חיבור נתונים ופקודות (State & Commands)

Connect the View cleanly to the ViewModel adhering to professional standards:
* **Compiled Bindings**: Add `x:DataType="viewmodels:MyScreenViewModel"` at page root.
* **Commands over Click Handlers**: Bind interactive elements to `ICommand` using `Command="{Binding SaveCommand}"`.
* **CanExecute**: Explain why `CanExecute` protects commands instead of manually toggling `IsEnabled` (refer to it as "עקרון פיתוח מקצועי", never as an internal agent rule).
* **Loading State**: Bind `IsRunning` and `IsVisible` of `ActivityIndicator` to `IsLoading` (never use `Page.IsBusy`).
* **ObservableCollection**: Explain why collections bound to `CollectionView` must be `ObservableCollection<T>`.

---

### Part 7: שאלות חזרה, הבנה ואתגר חשיבה (Three-Tier Thinking Framework)

Every guide and chapter MUST conclude with an active, didactic reflection section structured into 3 distinct tiers:

1. **דילמת ארכיטקטורה ועיצוב (Architectural Dilemma)**:
   - Present a realistic engineering tradeoff for the student to weigh (e.g. *"מתי נעדיף לחשב אגרגציות ב-SQL ומתי ב-ViewModel?"*, *"מה היתרון של Border מעוגל מול AbsoluteLayout?"*).
2. **שאלות הבנה מעמיקות עם רמזי הכוונה (In-Depth Questions with Clues)**:
   - Ask 2-3 conceptual questions testing *why* things were built this way, accompanied by expandable thinking clues (`[!TIP]`).
3. **אתגר מעשי קצר לתלמיד (Hands-on Mini-Challenge)**:
   - Provide a concrete task the student can implement independently (e.g. *"הוסף כרטיס סטטיסטי רביעי המציג את ממוצע משך הסרטונים"*), with step-by-step guidance and verification criteria.

## 📚 שפת התלמיד ודף מקורות (Student Tone & Bibliography Standard)

1. **Natural Textbook Voice**:
   - Never leak internal agent prompts or meta-rules into student-facing guides. Phrases like "חוק ברזל ב-K-12", "מצב Capability", "Baton Workflow", or "סוכן" are strictly forbidden in learning artifacts.
   - Use natural pedagogical Hebrew: "עקרון פיתוח מקצועי", "דפוס עיצוב מומלץ", "שיטת הבלוקים המודולרית (The Modular Block Strategy)".
2. **Appendix: Sources & Bibliography**:
   - Place all methodology inspirations, author credits (Leomaris Reyes, AskXammy.com, Telerik MVP), and official documentation links into a clean concluding section: `נספח: מקורות השראה, תיעוד וביבליוגרפיה` in small, professional typography.

## Visual Screenshot Flow (HTML/CSS Mockup -> Playwright/Browser Capture)

To generate authentic visual breakdown screenshots matching Leomaris's style:

1. **Write HTML Mockup**:
   - Create an HTML file in `Learning/Mockups/<ScreenName>.html`.
   - Use standard mobile CSS styles (390-412px width phone shell, modern fonts, gradients, cards, and SVG icons).
   - Add annotated color-coded block borders (`.block-1`, `.block-2`, etc.) and `.hero-banner`.
2. **Capture Element Screenshots**:
   - Run automated capture script (`Scripts/Capture-Mockup-Blocks.py`) using Playwright / headless Chromium to capture:
     - `Learning/Images/<ScreenName>-overview.png` (Full phone frame)
     - `Learning/Images/<ScreenName>-hero.png` (Hero banner)
     - `Learning/Images/<ScreenName>-block<N>-<name>.png` (Each individual block)
3. **Embed in Markdown**:
   - Embed the overview diagram in Part 1.
   - Embed the specific block image in Part 4 under each corresponding step.

## PDF Book Compilation Flow

To compile the entire Learning Book along with all modular guides into a publication-ready PDF:

1. **Integrated Script**:
   - The skill includes `scripts/generate_book_pdf.py` which auto-detects the project name from `.csproj`, scans all guides in `Learning/Guides/*.md`, embeds images as base64, applies print-perfect soft wrapping without scrollbars, and invokes headless Chrome/Edge.
2. **Project Deployment**:
   - `Scripts/Setup-Skills.ps1` automatically copies this script into the project's `Scripts/Generate-Learning-Book-Pdf.py` and provides a PowerShell wrapper `Scripts/Generate-Learning-Book-Pdf.ps1`.
3. **Execution**:
   - Run `python .\Scripts\Generate-Learning-Book-Pdf.py` (or `.\Scripts\Generate-Learning-Book-Pdf.ps1`) to produce `Learning/MAUI-Learning-Book.pdf`.
